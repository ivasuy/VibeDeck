Deviations

Historical recent activity depth

Spec quote: Attribution Health uses Pattern F half-gauge. Center label text-h2.

What I did: Replaced the placeholder attribution card with a real half-gauge sourced from /functions/vibedeck-attribution-stats. Recent Activity now prefers exact live/recent session rows from /functions/vibedeck-sessions-live-snapshot, then falls back to aggregate period rows when no recent session rows exist.

Justification: The attribution health metric now has a real backend numerator/denominator. The dashboard also reads exact historical canonical session rows through /functions/vibedeck-recent-sessions, so the aggregate period fallback is only for missing/unavailable local history.

macOS app shell source of truth

Spec quote: Sidebar spec: Width: 220pt fixed.

What I did: Added a SwiftUI NavigationSplitView wrapper around the existing macOS WKWebView detail instead of replacing the web-hosted dashboard with separate native implementations for every tab.

Justification: The current app routes dashboard auth, settings, and bridge messages through the web shell. The native split wrapper satisfies the window/sidebar structure while avoiding duplicated dashboard business logic and preserving the bridge contracts already used by the app.

Dashboard recent activity granularity

Spec quote: Recent Activity is Tier 1 (no card around the list). 5 rows max. Each row 40px tall.

What I did: Used exact live/recent session rows plus historical canonical recent-session rows when present, capped at five rows, and kept the section uncarded; aggregate period rows remain the fallback when local session history is unavailable.

Justification: The combined live snapshot and recent-session endpoint covers active, recently ended, and historical rows without inventing session filenames or metrics.

Skills usage attribution data

Spec quote: List of detected Claude Code / Codex skills sorted by usage. Each row: skill name, invocation count, cost attributed, link to skill source.

What I did: Added a read-only skills usage mode backed by stored session skills_json counters, sorted rows by invocation count, apportioned known session cost by each skill's share of recorded skill calls, and linked usage rows to installed skill source metadata when available.

Justification: This keeps the numbers tied to recorded provenance. If a session has no known cost, its skill calls still count but do not create fake attributed dollars.

Tradeoffs

Revamp scope sequencing

Alternatives considered: implement web, macOS, widgets, menubar, motion, and backend data wiring in one pass; or ship the spec's own incremental order.

Choice: ship the web dashboard shell and highest-visibility surfaces first, then audit remaining surfaces.

Reason: the spec spans 17 implementation chunks across three surfaces. Starting with shared web tokens, navigation, logos, and page composition lowers design debt without destabilizing native/widget code before the dashboard patterns are proven.
